# BusBus — транспорт онлайн без рекламы

Онлайн-карта общественного транспорта **Новосибирска** и **Красноярска**: где сейчас автобус, троллейбус, трамвай или маршрутка, через сколько минут он будет на нужной остановке.

- 🚌 Реальные данные официальных порталов: [map.nskgortrans.ru](https://map.nskgortrans.ru/) (МКУ «ЦУГАЭТ») и [mu-kgt.ru](https://mu-kgt.ru/informing/wap/marsh/) (МКУ «Красноярскгортранс»).
- 📱 Android-приложение (APK) и веб-версия / PWA с одним и тем же интерфейсом.
- 🧪 Демо-режим: полностью автономная симуляция движения — интерфейс можно смотреть без сети.
- 🚫 Никакой рекламы, аналитики и трекеров.

## Что умеет

| Возможность | Новосибирск | Красноярск |
| --- | --- | --- |
| Координаты машин на карте | ✅ GPS с источника | ➖ позиция по остановкам |
| Скорость и курс машины | ✅ | ➖ |
| Линия маршрута по улицам | ✅ (`trasses.php` + OSRM) | ✅ (схема в демо-данных) |
| Остановки маршрута с id | ✅ (`trasses.php`) | ➖ |
| Ближайшие остановки с прогнозом | ✅ | ✅ |
| Список маршрутов по типам транспорта | ✅ (104) | ✅ (69) |
| Табло остановки | ✅ (`forecast.php`, минуты) | ✅ |
| Тёмная карта, геолокация, избранное | ✅ | ✅ |

Красноярский портал не публикует GPS-координаты — только позицию машины «в очереди» между остановками
(«менее 370 метров до …»). BusBus показывает такие машины на линии маршрута в соответствующей точке и
помечает значком «≈ позиция», чтобы не выдавать приблизительное за точное.

## Структура репозитория

```
core/    общая библиотека: провайдеры данных, карта (Leaflet), экраны, тема
web/     веб-версия и PWA: сборка Vite, манифест, service worker, single-file бандл для APK
apk/     Android-обёртка (WebView + нативный HTTP-мост, без CORS-прокси)
scripts/ сбор данных: build-geo.mjs (геометрия по улицам), snapshot.mjs (срез для веба)
ci/      артефакты CI: скриншоты интерфейса, APK
```

Служебные ветки, которые ведут workflows (смотреть не обязательно):

| Ветка | Что внутри |
| --- | --- |
| `ci/apk` | свежий APK (`ci/apk/busbus.apk`) |
| `ci/pages` | собранная PWA + APK для скачивания |
| `ci/live` | срез живых данных `data/live/{nsk,krsk}.json` (каждые 10 минут) |
| `ci/shots` | скриншоты интерфейса и отчёт `live-check.txt` |
| `ci/geo` | геометрия маршрутов, собранная `build-geo.mjs` |

`core` не зависит от платформы: те же экраны открываются в браузере и в WebView Android.
Единственное отличие — HTTP-слой: в браузере это `fetch`, в APK — нативный мост.

## Быстрый старт (разработка)

```bash
cd core && npm install
cd ../web && npm install
npm run dev          # http://localhost:5173
```

Полезные команды:

```bash
cd core && npm run typecheck     # строгая проверка типов
cd web && npm run build          # PWA для GitHub Pages
cd web && npm run build:android  # single-file HTML → apk/app/src/main/assets/index.html
cd apk && gradle assembleDebug   # APK (нужен Android SDK)
```

## Android-приложение

**Готовый APK:** [последний релиз](https://github.com/kos19191/busbus/releases/latest)
(`busbus-<версия>.apk`, ~1.6 МБ). Требуется Android 6.0+.

Сборка APK — в GitHub Actions:

* `release.yml` — по пушу тега `vX.Y.Z` собирает release-APK (R8 + shrink), проверяет badging
  и публикует GitHub Release с вложенным файлом. Если в секретах репозитория лежит keystore
  (`BUSBUS_KEYSTORE_B64`, `BUSBUS_KEYSTORE_PASSWORD`, `BUSBUS_KEY_ALIAS`, `BUSBUS_KEY_PASSWORD`),
  APK подписывается им; иначе — debug-ключом CI (для личной установки этого достаточно,
  для Google Play нужен свой keystore).
* `android.yml` — на каждый пуш собирает debug- и release-APK в ветку `ci/apk`.

Как выпустить новую версию:

```bash
# 1) поднять версию
printf 'versionName=1.3.0\nversionCode=4\n' > apk/version.properties
# 2) обновить текст релиза
$EDITOR .github/release-notes.md
# 3) закоммитить, поставить тег и запушить его — workflow соберёт и опубликует релиз
git commit -am "release: 1.3.0" && git tag v1.3.0 && git push origin HEAD v1.3.0
```

Почему нужен отдельный APK, если есть сайт: официальные порталы не отдают CORS-заголовки,
поэтому в обычном браузере живые данные получить нельзя. В приложении используется нативный
HTTP-мост (`JavascriptInterface`), который забирает данные без ограничений браузера — быстро и без прокси.

## Веб-версия и GitHub Pages

`npm run build` собирает PWA. Workflow `pages.yml` публикует сборку в ветку `ci/pages`;
чтобы открыть её как сайт, включите Pages: **Settings → Pages → Source: Deploy from a branch →
`ci/pages` / root**. Тогда PWA будет на `https://<логин>.github.io/busbus/`, а APK — по ссылке
`/busbus.apk` с той же страницы. Если включить `Source: GitHub Actions`, тот же workflow
задеплоит сборку штатным способом.

Без публичного прокси живые данные в браузере не загрузятся (CORS), поэтому веб-версия стартует
в демо-режиме. В «Настройках» можно указать собственный прокси-шаблон вида
`https://ваш-прокси/?url={url}` — тогда в браузере тоже будут реальные автобусы.

## Источники данных и честность

* **Новосибирск** — публичные эндпоинты сайта ЦУГАЭТ: `listmarsh.php`, `markers.php`,
  `forecast.php` (табло в минутах), `trasses.php` (линия по улицам и остановки с id).
  Важная деталь: в id маршрута `type` — это `listmarsh.type + 1` (автобус `1-`, троллейбус `2-`,
  трамвай `3-`, маршрутка `8-`), иначе `markers.php` возвращает пустой список.
  Разбор — в `core/src/transport/nsk.ts`.
* **Красноярск** — публичный JSON мобильной версии: `?m=<маршрут>&action=getMarshData`
  (`core/src/transport/krsk.ts`).
* Данные принадлежат операторам; приложение только отображает их и не связано с перевозчиками.
* Точность прогнозов зависит от источника. Позиция машины в Красноярске — расчётная.
* Геометрия демо-маршрутов строится в `scripts/build-geo.mjs`: порядок остановок берётся из
  `trasses.php` ЦУГАЭТ, линия прокладывается по улицам через публичный OSRM.

## Как обновляются данные

| Канал | Задержка | Что использует |
| --- | --- | --- |
| APK (нативный мост) | 12 секунд | напрямую `map.nskgortrans.ru` / `mu-kgt.ru` |
| Веб (срез) | 10 минут + интерполяция позиций | `raw.githubusercontent.com/.../ci/live` |
| Демо | реальное время симуляции, без сети | встроенные линии по улицам |

## Проверка источников

`web/scripts/lib-check.mjs` дёргает живые API и печатает отчёт (маршруты, машины, координаты,
линия, остановки, табло). В CI он выполняется в `ui-check.yml` и публикуется вместе со
скриншотами в `ci/shots/live-check.txt`.
